# File-local types (C# 11)

> **Abstract.** The `file` modifier restricts a top-level type to the **source file** that declares it. Two files
> can each declare a `file class Helper` without conflict. This is the narrowest accessibility in C#, designed for
> source generators and for helpers that belong to exactly one file.

| | |
|---|---|
| Introduced | C# 11 · .NET 7 (`net7.0`) |
| Status | Stable |
| Kind | Syntax (accessibility modifier) |
| Runtime support needed | No |
| Audience | Everyday code, source-generator authors |
| Modernize category | PREFER |

## 1. Motivation

`internal` helpers are visible to the whole assembly and collide by name; `private` nested types force nesting
inside an unrelated class. Source generators had it worst: two generators emitting `internal class Helpers` into the
same namespace break the build.

## 2. The feature explained

### 2.1 Syntax

```csharp
file class Helper { }
file static class Constants { }
file record struct Key(int A, int B);
file interface IVisitor { }
```

### 2.2 Semantics and rules

1. Allowed on top-level (non-nested) types: class, struct, record, interface, enum, delegate.
2. Not allowed on members, and not combinable with other accessibility modifiers.
3. A file-local type can only be used in its file.
4. It cannot appear in the signature of a non-file-local member (return, parameter, base type of a public type, ...).
5. A file-local type **can** implement public interfaces and be returned as that interface.
6. Nested types inside a file-local type are effectively file-local too.

## 3. Code examples

### 3.1 Minimal example

```csharp
file static class SaveFormatConstants
{
    public const int Version = 3;
}

public sealed class SaveService
{
    public int CurrentVersion => SaveFormatConstants.Version;
}
```

### 3.2 Extended examples

Hidden implementation of a public interface:

```csharp
public interface IPathCache { bool TryGet(int from, int to, out int[] path); }

public static class PathCaches
{
    public static IPathCache CreateDefault() => new LruPathCache(256);
}

file sealed class LruPathCache : IPathCache
{
    private readonly int _capacity;
    public LruPathCache(int capacity) => _capacity = capacity;
    public bool TryGet(int from, int to, out int[] path) { path = Array.Empty<int>(); return false; }
}
```

Source generator output that never clashes:

```csharp
// <auto-generated/> EnemyStats.g.cs
file static class GeneratedHelpers
{
    public static int Clamp(int v) => Math.Clamp(v, 0, 999);
}

partial class EnemyStats
{
    public int SafeHp => GeneratedHelpers.Clamp(Hp);
}
```

A file-local comparer:

```csharp
public static class Leaderboard
{
    public static void Sort(List<Score> scores) => scores.Sort(new ByPointsDescending());
}

file sealed class ByPointsDescending : IComparer<Score>
{
    public int Compare(Score? a, Score? b) => (b?.Points ?? 0).CompareTo(a?.Points ?? 0);
}
```

## 4. Before this feature

```csharp
public sealed class SaveService
{
    private static class SaveFormatConstants { public const int Version = 3; }   // nested only to hide it
}

internal static class SaveServiceHelpers { }   // visible to the whole assembly; name clashes possible
```

## 5. Under the hood

The compiler mangles the metadata name so it is unique per file, using the file name and a checksum of the file path,
roughly `<SaveService>F3A1B2C4__SaveFormatConstants`. The type is `internal` in metadata. Reflection sees the mangled name.

## 6. Performance and allocation

None.

## 7. Pitfalls

- Reflection, serialization by type name, or DI registration by name sees the **mangled** name.
- Moving a file-local type's consumer to another file breaks the build (intended).
- Partial classes split across files cannot share a file-local helper, and all parts of a `file partial` type must
  live in the same file. A source generator therefore cannot complete a user's `file partial` type from another file.

## 8. Concerns and limitations

- Tests cannot reach file-local types (not even via `InternalsVisibleTo`). Test through the public surface.
- Godot: do not make Godot script classes (`Node`-derived) file-local; the engine looks types up by name.

## 9. When to use: clean-code guidance

### 9.1 Use when
- Helpers, constants, comparers or DTOs used by exactly one file.
- Code emitted by source generators.

### 9.2 Avoid when
- The type is reused by other files or needs direct unit tests.

### 9.3 Good versus bad

```csharp
// Good: comparer used only here
file sealed class ByDistance : IComparer<Node2D> { ... }

// Bad: shared domain type hidden in one file, duplicated elsewhere
file record Item(string Id);
```
