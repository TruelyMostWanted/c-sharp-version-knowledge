# Warning wave 7 (C# 11)

> **Abstract.** Warning waves are sets of new compiler warnings that are enabled only when a project opts into a
> newer analysis level (by default, the level of its target framework). Wave 7 (.NET 7) brought **CS8981**:
> a type name consisting only of lowercase ASCII letters may collide with future contextual keywords. This is
> exactly how `record`, `required`, `field` or `scoped` break old code.

| | |
|---|---|
| Introduced | C# 11 · .NET 7 (`net7.0`) |
| Status | Stable |
| Kind | Diagnostics |
| Runtime support needed | No |
| Audience | Everyone |
| Modernize category | CASE (rename) |

## 1. Motivation

New C# versions add **contextual keywords** (`var`, `record`, `init`, `required`, `scoped`, `file`, `field`,
`extension`, `union`, `closed`, ...). If a project already has a type named like that, the new meaning can either break
compilation or silently change behaviour. The language team reserves all-lowercase type names for future keywords
and warns about them.

## 2. The feature explained

### 2.1 Syntax

Configure the analysis level:

```xml
<AnalysisLevel>latest</AnalysisLevel>      <!-- or 7, 8, ... ; default follows the TFM -->
<WarningLevel>7</WarningLevel>            <!-- compiler warning wave explicitly -->
```

### 2.2 Semantics and rules

1. Warning waves are enabled by `<AnalysisLevel>` / `<WarningLevel>`; on `net7.0`+ wave 7 is on by default.
2. **CS8981**: "The type name only contains lower-cased ascii characters. Such names may become reserved for the language."
3. Existing code still compiles; the warning becomes an error only with `TreatWarningsAsErrors`.
4. Earlier waves: wave 5 (.NET 5, e.g. CS8073 comparisons with null on structs), wave 6 (.NET 6), later waves add more; see the reference.

## 3. Code examples

### 3.1 Minimal example

```csharp
class record { }      // CS8981 (and conflicts with the record keyword in some positions)
class vec2 { }        // CS8981
class Vec2 { }        // fine
```

### 3.2 Extended examples

How a lowercase name breaks with a newer keyword (C# 14 `field`):

```csharp
class Item
{
    private int field;                       // a member called "field"
    public int Value
    {
        get => field;                        // C# 13: the member; C# 14: the synthesized backing field!
        set => field = value;
    }
}
```

The fix is to rename (`_field`) or write `this.field` / `@field`.

Lowercase type names generated by tools (protobuf, scaffolding):

```csharp
#pragma warning disable CS8981   // generated code; do not rename by hand
public partial class msg_header { }
#pragma warning restore CS8981
```

## 4. Before this feature

No warning; collisions surfaced only when a new language version made the name a keyword.

## 5. Under the hood

Diagnostics only; no effect on generated IL.

## 6. Performance and allocation

None.

## 7. Pitfalls

- Suppressing CS8981 project-wide hides the early warning it exists for.
- Member names (fields, locals) are **not** covered by CS8981 but can still collide (see `field` example).

## 8. Concerns and limitations

- Renaming public types is a breaking change; treat as CASE.

## 9. When to use: clean-code guidance

### 9.1 Use when
- Always keep wave 7 enabled. Name types in PascalCase.

### 9.2 Avoid when
- Suppress only for generated code you cannot change.

### 9.3 Good versus bad

```csharp
// Good
public sealed class Union { }

// Bad
public sealed class union { }    // `union` is a contextual keyword in C# 15
```

Agent rule: never name types in all lowercase, and avoid members named after contextual keywords (`field`, `value`, `extension`).
