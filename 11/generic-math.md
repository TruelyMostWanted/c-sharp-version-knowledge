# Generic math and static abstract interface members (C# 11 / .NET 7)

> **Abstract.** Interfaces can declare `static abstract` and `static virtual` members, including **operators**.
> .NET 7 builds a family of numeric interfaces on this (`INumber<T>`, `IFloatingPoint<T>`,
> `IAdditionOperators<TSelf, TOther, TResult>`, ...), so a numeric algorithm can be written once with
> `where T : INumber<T>` and used for `int`, `float`, `double`, `decimal`, `Half`, `BigInteger` and your own types.
> The JIT specializes the code per value type, so there is no boxing and no virtual call cost.

## 1. Motivation

Generic code could not use operators or static members of `T`: `T + T` and `T.Zero` did not exist.
Numeric code was duplicated per type (`Sum(int[])`, `Sum(float[])`, `Sum(double[])`), generated by T4 templates,
or written with `dynamic` (slow, boxing). Interfaces could only describe **instance** members.

## 2. The feature explained

### 2.1 Syntax

```csharp
public interface IMonoid<TSelf> where TSelf : IMonoid<TSelf>
{
    static abstract TSelf Identity { get; }
    static abstract TSelf operator +(TSelf a, TSelf b);
    static virtual TSelf Combine(TSelf a, TSelf b) => a + b;   // default implementation
}

static T Fold<T>(ReadOnlySpan<T> xs) where T : IMonoid<T>
{
    T acc = T.Identity;
    foreach (var x in xs) acc += x;
    return acc;
}
```

### 2.2 Semantics and rules

1. `static abstract` members must be implemented by every implementing type; `static virtual` members have a default.
2. They are accessed **through a type parameter** (`T.Zero`, `a + b` with `T : IAdditionOperators<T,T,T>`), never via the interface name.
3. An interface with static abstract members cannot be used as a **type argument** (error CS8920), because there would be no implementation to call.
4. The curiously recurring pattern `where TSelf : IFoo<TSelf>` lets members mention the implementing type.
5. Related C# 11 additions in the same feature set:
   - `checked` user-defined operators: `public static T operator checked +(T a, T b)`.
   - Unsigned right shift `>>>`.
   - Relaxed shift operators: the right operand of `<<` / `>>` need not be `int` in user-defined operators.

Key BCL interfaces: `INumberBase<T>` (`Zero`, `One`, parsing, `CreateChecked/Saturating/Truncating`),
`INumber<T>` (comparison, `Min`, `Max`, `Clamp`), `IBinaryInteger<T>`, `IFloatingPoint<T>`,
`IFloatingPointIeee754<T>` (`Sqrt`, `Sin`, ...), plus operator interfaces (`IAdditionOperators`, `IMultiplyOperators`, ...).

## 3. Code examples

### 3.1 Minimal example

```csharp
static T Sum<T>(ReadOnlySpan<T> values) where T : INumber<T>
{
    T total = T.Zero;
    foreach (var v in values) total += v;
    return total;
}

int   a = Sum<int>(new[] { 1, 2, 3 });
float b = Sum<float>(new[] { 0.5f, 1.5f });
```

### 3.2 Extended examples

Average with conversion between numeric types:

```csharp
static TResult Average<T, TResult>(ReadOnlySpan<T> values)
    where T : INumber<T>
    where TResult : INumber<TResult>
{
    T sum = T.Zero;
    foreach (var v in values) sum += v;
    return TResult.CreateChecked(sum) / TResult.CreateChecked(values.Length);
}

double avg = Average<int, double>(new[] { 1, 2, 4 });   // 2.333...
```

Linear interpolation for any floating-point type:

```csharp
static T Lerp<T>(T from, T to, T t) where T : IFloatingPoint<T>
    => from + (to - from) * T.Clamp(t, T.Zero, T.One);

float  f = Lerp(0f, 10f, 0.25f);
double d = Lerp(0.0, 10.0, 0.25);
```

Own numeric-like type implementing operator interfaces:

```csharp
public readonly record struct Stat(int Value) :
    IAdditionOperators<Stat, Stat, Stat>,
    IAdditiveIdentity<Stat, Stat>
{
    public static Stat AdditiveIdentity => new(0);
    public static Stat operator +(Stat a, Stat b) => new(a.Value + b.Value);
}

static T SumAll<T>(IEnumerable<T> xs) where T : IAdditionOperators<T, T, T>, IAdditiveIdentity<T, T>
{
    T acc = T.AdditiveIdentity;
    foreach (var x in xs) acc += x;
    return acc;
}
```

Static factory contract (no numbers involved):

```csharp
public interface IParsableConfig<TSelf> where TSelf : IParsableConfig<TSelf>
{
    static abstract TSelf Parse(string text);
}

static T Load<T>(string path) where T : IParsableConfig<T> => T.Parse(File.ReadAllText(path));
```

`>>>` and checked operators:

```csharp
int x = -16;
int arithmetic = x >> 2;    // -4 (sign-extended)
int logical    = x >>> 2;   // 1073741820 (zero-filled)

public readonly record struct Fixed(int Raw)
{
    public static Fixed operator +(Fixed a, Fixed b) => new(a.Raw + b.Raw);
    public static Fixed operator checked +(Fixed a, Fixed b) => new(checked(a.Raw + b.Raw));
}
```

## 5. Under the hood

Static abstract members are emitted as `static abstract virtual` methods in the interface. Calls through a type
parameter use a **constrained call**:

```
// T.Zero inside Sum<T>
constrained. !!T
call !0 class System.Numerics.IAdditiveIdentity`2<!!T, !!T>::get_AdditiveIdentity()
```

At runtime the JIT resolves the constrained call to the concrete implementation. For **value types** each
instantiation (`Sum<int>`, `Sum<float>`) gets its own native code, so the call is direct and usually inlined:
the generated machine code is as fast as the hand-written overload. For reference types, shared generic code
uses a runtime lookup.

## 6. Performance and allocation

- Value-type instantiations: no boxing, no interface dispatch, inlinable. Same speed as specialized code.
- Vectorization is not automatic: for bulk work prefer `System.Numerics.Vector<T>` / `TensorPrimitives` (which themselves use generic math).
- Code size grows with the number of value-type instantiations.

## 7. Pitfalls

- Static abstract members are callable only through a type parameter (`T.Zero`), not through the interface itself.
- `CreateChecked` throws on overflow, `CreateSaturating` clamps, `CreateTruncating` wraps; choose deliberately.
- Integer division and floating-point division differ: generic code `a / b` truncates for integers.
- Godot's `Vector2`, `Vector3`, `Color` do **not** implement the generic math interfaces; use generic math for scalar code, or write your own interfaces.
- Interfaces with static abstract members cannot be type arguments (CS8920), so `List<INumber<int>>`-style designs do not work; APIs must stay generic all the way down.

## 8. Concerns and limitations

- Readability: deep constraint lists (`where T : IBinaryInteger<T>, IMinMaxValue<T>`) intimidate readers. Prefer the broadest suitable interface (`INumber<T>`).
- Binary compatibility: adding a `static abstract` member to a published interface breaks all implementers. Use `static virtual` with a default for evolution.
- Requires the .NET 7+ runtime; not available on `netstandard2.0` (see [../15/static-interface-members-older-runtimes.md](../15/static-interface-members-older-runtimes.md) for the narrow C# 15 exception).

## 9. When to use: clean-code guidance

### 9.1 Use when
- The same numeric algorithm is needed for several types (statistics, interpolation, fixed-point vs float, units).
- Defining static contracts (factories, parsers, identities) for generic code.

### 9.2 Avoid when
- Only one numeric type is ever used: write it for that type.
- The code is a per-frame hot path over Godot vectors: use the engine types directly.

### 9.3 Good versus bad

```csharp
// Good
static T Clamp01<T>(T v) where T : INumber<T> => T.Clamp(v, T.Zero, T.One);

// Bad: over-constrained, unreadable, used only with float
static T Clamp01<T>(T v) where T : IFloatingPointIeee754<T>, IMinMaxValue<T>, IBinaryNumber<T> => ...;
```
