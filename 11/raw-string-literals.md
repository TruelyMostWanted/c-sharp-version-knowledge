# Raw string literals (C# 11)

> **Abstract.** A raw string literal starts and ends with **three or more** double quotes (`"""`). Its content is
> taken literally: no escape sequences, quotes need no doubling. In the multi-line form the indentation of the
> closing delimiter is stripped from every line, so embedded JSON, SQL, shaders or code templates can be indented
> with the surrounding C#. Interpolated raw strings use `$` signs to decide how many braces open a hole.

## 1. Motivation

Embedding text formats in C# was painful:

```csharp
string json = "{\n  \"name\": \"Ann\"\n}";             // escaped quotes and newlines
string json2 = @"{
  ""name"": ""Ann""
}";                                                  // doubled quotes, must start at column 0
string tpl = $"{{ \"id\": {id} }}";                   // doubled braces in interpolation
```

## 2. The feature explained

### 2.1 Syntax

```csharp
string single = """He said "hi" and left""";           // single-line form

string multi = """
    line 1
      line 2 (indented by 2)
    """;                                               // closing delimiter defines the margin

string interp = $"""Hello {name}""";                  // one $ -> {expr} is a hole
string json   = $$"""{ "id": {{id}} }""";             // two $ -> {{expr}} is a hole, { } literal
```

### 2.2 Semantics and rules

1. The delimiter is N ≥ 3 quotes; the content may contain any run of fewer than N quotes. Use `""""` if the text contains `"""`.
2. **Single-line**: content on the same line as both delimiters; it cannot start or end with a quote character.
3. **Multi-line**: the opening delimiter must be followed by a newline; the closing delimiter must be on its own line.
   The first and last newlines are not part of the content.
4. The whitespace **before the closing delimiter** is removed from every content line; every non-empty line must start with exactly that whitespace (error otherwise).
5. No escape sequences: `\n` is two characters.
6. Interpolation: with M `$` signs, a hole is opened by M braces (`{` × M) and fewer braces are literal text.
   Format specifiers work as usual: `{{value:F2}}`.
7. Raw strings can be `const` when not interpolated (or when interpolated only with constant strings, C# 10 rules).
8. A raw string is an ordinary `string`; the `u8` suffix also works (`"""..."""u8`).

## 3. Code examples

### 3.1 Minimal example

```csharp
string json = """
    {
      "name": "Ann",
      "tags": ["a", "b"]
    }
    """;
```

### 3.2 Extended examples

Interpolated JSON (braces stay literal):

```csharp
string payload = $$"""
    {
      "unit": "{{unit.Id}}",
      "pos": { "x": {{pos.X:F2}}, "y": {{pos.Y:F2}} }
    }
    """;
```

GDShader template:

```csharp
string shader = $$"""
    shader_type canvas_item;
    uniform float speed = {{speed}};
    void fragment() {
        COLOR.a *= 0.5;
    }
    """;
```

SQL:

```csharp
const string Query = """
    SELECT id, name
    FROM units
    WHERE hp > 0
    ORDER BY name;
    """;
```

Regular expressions without double escaping:

```csharp
var re = new Regex("""^(?<key>[a-z_]+)\s*=\s*"(?<value>[^"]*)"$""");
```

Source generator output:

```csharp
string source = $$"""
    // <auto-generated/>
    namespace {{ns}};

    partial class {{className}}
    {
        public static string Name => "{{className}}";
    }
    """;
```

Test fixture whose content contains `"""` (needs a four-quote delimiter):

```csharp
const string Csv = """"
    id,name,"description"
    1,Archer,"Shoots ""arrows"""
    """";
```

## 4. Before this feature

```csharp
string json = @"{
  ""name"": ""Ann"",
  ""tags"": [""a"", ""b""]
}";

string payload = $"{{ \"unit\": \"{unit.Id}\" }}";
```

## 5. Under the hood

Lexer-only feature. The compiler computes the final content (margin removed) and emits it as an ordinary string
literal (`ldstr`). Interpolated raw strings lower exactly like other interpolated strings
(`DefaultInterpolatedStringHandler`, constant folding, ...).

## 6. Performance and allocation

None beyond normal string literals and interpolation.

## 7. Pitfalls

- Mixed tabs and spaces in the margin cause errors: the whitespace prefix must match exactly.
- The line ending style of the source file (CRLF vs LF) becomes part of the string. Normalize with `.gitattributes`
  or `ReplaceLineEndings()` if the output must be stable across platforms.
- With `$$`, a single `{` is literal, so `{name}` silently stays text; you need `{{name}}`.
- Single-line raw strings cannot begin or end with `"`: use the multi-line form.

## 8. Concerns and limitations

- Some older tools (syntax highlighters, linters) mis-color raw strings; the compiler is the authority.
- Large embedded resources belong in files (`res://`, embedded resources), not in source.

## 9. When to use: clean-code guidance

### 9.1 Use when
- JSON, SQL, regex, XML, GDShader or code templates in source, test fixtures, source generators.

### 9.2 Avoid when
- Short strings without quotes or backslashes: a normal literal is fine.
- Large or user-editable text: load from a file.

### 9.3 Good versus bad

```csharp
// Good
var pattern = new Regex("""\d+\.\d+""");

// Bad
var pattern2 = new Regex("\\d+\\.\\d+");
```
